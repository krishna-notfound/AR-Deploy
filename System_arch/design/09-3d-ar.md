# 09 · 3D viewer & AR
Read when: working on ModelViewer3D, ModelPreview, AR button, AR tips, in-app notice, or sample models.
Decision: [ADR-0006](../decisions/ADR-0006-ar-fixed-scale-check.md)

## model-viewer setup
- Load with a dynamic `import('@google/model-viewer')`. Declare JSX types in `src/types/model-viewer.d.ts` (React 19: `declare module 'react' { namespace JSX { interface IntrinsicElements {...} } }`).
```html
<model-viewer src={glb.url} ios-src={usdz?.url /* only when a valid USDZ exists */}
  poster={primaryImage.url} alt={name}
  camera-controls touch-action="pan-y" shadow-intensity="1"
  ar ar-modes="webxr scene-viewer quick-look" ar-scale="fixed" ar-placement="floor">
  <button slot="ar-button">View in my home</button>
  <div slot="progress-bar"/>
</model-viewer>
```
- Events to handle: `load`, `error`, `progress`, `ar-status`, `ar-tracking`.

## States (ModelViewer3D)
| State | UI |
|---|---|
| No GLB | Gallery is the main view, with the note "3D view not available for this product yet". AR button hidden. |
| Loading | Poster plus a thin progress bar |
| Loaded | Hint: "Drag to rotate · pinch to zoom" |
| Error | Poster, the message "We couldn't load the 3D model", and Retry. The gallery still works. |

## "View in my home" (as built)
- The built-in `ar-button` slot is hidden. Our own prominent button sits in the product info column (`ArSection`).
- After the `load` event, the button appears **only when model-viewer reports `canActivateAR`**, which is the library's real capability check. On click it calls `viewer.activateAR()`. Availability states:
  - `checking`: the model is still loading.
  - `available`: the device can launch AR.
  - `unavailable`: show the phone hand-off panel.
  - `none`: there is no model, or it failed to load.
- The viewer stays mounted (hidden) while the Photos tab is shown, so AR can still launch from it.
- On devices without AR, show: "AR is available on compatible phones and tablets." Offer Copy link and an optional small QR code of **this page** for handing off to a phone.
- On click:
  1. `recordEvent({type:'ar_activation'})`.
  2. Show the AR tips first if the user hasn't dismissed them.
- On `ar-status: failed`, show the toast "AR couldn't start on this device. You can still explore the 3D model."

## Accurate scale
- Always display dimensions as `W × H × D unit`. A cm/in toggle changes the display only; the stored unit stays the source of truth.
- `ar-scale="fixed"` stops users from resizing the model in AR.
- **Scale check:** after `load`, compare `viewer.getDimensions()` (meters) with the entered dimensions, mapping x→W, y→H, z→D, with ±5 % tolerance.
  - All three within tolerance: badge "True-to-size model ✓".
  - Otherwise: badge "AR scale unverified", with a tooltip showing measured vs entered values.
- **Never** change `scale` to force a match. The admin ModelPreview shows the same check.

## AR tips (ArTips)
A dismissible bottom sheet on mobile, a popover on desktop. Steps:
1. Point the camera at the floor.
2. Move slowly to scan.
3. Tap to place.
4. Drag to move, two fingers to rotate.

"Don't show again" sets `arfurn:arTipsDismissed`. An "AR tips" link reopens the panel. All text is translated.

## In-app browser notice
- `detectInAppBrowser(ua)` returns `'instagram' | 'facebook' | 'whatsapp' | null`, matching `/Instagram/i`, `/FBAN|FBAV|FB_IAB/i`, and `/WhatsApp/i`.
- When it matches, show a dismissible banner: "For the best AR experience, open this page in Safari or Chrome", plus Copy link. Never promise that AR is blocked.

## Sample models (see [ADR-0013](../decisions/ADR-0013-sample-assets-measured.md) for what shipped)
- Use Khronos glTF-Sample-Assets GLBs (e.g. SheenChair, GlamVelvetSofa, ChairDamaskPurplegold). **Verify that each URL loads and that CORS allows it.** Fall back to copies in `public/models/`.
- Add USDZ only when a properly licensed file exists.
- The seed must also include products with **no model** and one with a **broken model URL**, so the fallback states can be tested.
- When `ios-src` is missing, model-viewer may generate a USDZ for Quick Look on its own. That is library behaviour; never present it as our feature. The editor still warns "No USDZ: iOS Quick Look may be unavailable or less reliable".
