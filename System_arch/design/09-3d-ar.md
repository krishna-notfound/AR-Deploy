# 09 · 3D viewer & AR
Read when: working on ModelViewer3D, ModelPreview, AR button, AR tips, in-app notice, or sample models.
Decision: [ADR-0006](../decisions/ADR-0006-ar-fixed-scale-check.md), [ADR-0018](../decisions/ADR-0018-custom-webxr-placement.md) (AR modes)

## model-viewer setup
- Load with a dynamic `import('@google/model-viewer')`. Declare JSX types in `src/types/model-viewer.d.ts` (React 19: `declare module 'react' { namespace JSX { interface IntrinsicElements {...} } }`).
```html
<model-viewer src={glb.url} ios-src={usdz?.url /* only when a valid USDZ exists */}
  poster={primaryImage.url} alt={name}
  camera-controls touch-action="pan-y" shadow-intensity="1"
  ar ar-modes="scene-viewer quick-look" ar-scale="fixed" ar-placement="floor">
  <button slot="ar-button">View in my home</button>
  <div slot="progress-bar"/>
</model-viewer>
```
- Events to handle: `load`, `error`, `progress`, `ar-status`, `ar-tracking`.

## States (ModelViewer3D)
| State | UI |
|---|---|
| No GLB | Gallery is the main view, with the note "3D view not available for this product yet". AR button hidden. |
| Loading | Poster plus a thin progress bar |
| Loaded | Hint: "Drag to rotate · pinch to zoom" |
| Error | Poster, the message "We couldn't load the 3D model", and Retry. The gallery still works. |

## AR modes (ADR-0018, `src/features/ar/`)
`chooseArMode()` picks one path by capability, never by user agent:
| Mode | When | What runs |
|---|---|---|
| `webxr` | `navigator.xr.isSessionSupported('immersive-ar')`. Chrome reports this on **every** Android 7+ phone, ARCore or not (audit §2) | Our session: `webxrSession.ts` + `ArSessionOverlay.tsx` (WebXR DOM overlay) |
| `native` | model-viewer `canActivateAR` (iOS Quick Look, Scene Viewer; a user-agent check on Android) and no `ar-status: failed` yet | `viewer.activateAR()`. With `webxrBeta`, a secondary "Precise placement (beta)" link starts our session |
| `none` | Neither, or no model / model error | 3D viewer + phone hand-off |
| `checking` | Model loading or capability unknown | Disabled button with spinner |

**Order** (`AR_DEFAULT_PREFERENCE` in `capability.ts`):
- **Today: `'webxr'` first.** Native-first (`'native'`) is implemented and tested but waits for client approval (audit APPROVAL_REQUIRED A-1).
- **Mode `none` with reason `failed`:** every path failed on this page. The page shows a notice and keeps the 3D view, with no AR button and no "open on a phone" hand-off.
- **Remembered failure:** a WebXR start that fails with `NotSupportedError` is remembered for 7 days (`arfurn:webxrUnavailable`), so the next visit goes straight to the native viewer. A cancel (`AbortError`) is never treated as a failure.

Our session flow (one instruction at a time, `placement.ts` reducer, unit-tested):
- **scanning** "Move your phone slowly to find the floor" → **aiming** (reticle on an upward surface 0.3–8 m away) → "Place here" button or screen tap → **placed**.
- **placed**: Rotate left/right 15°, Move (item follows the reticle; Place here / Cancel), Start over. No drag or pinch gestures; scale never changes.
- Tracking lost: actions pause, hint says so. Anchors used when available. Contact shadow under the item.
- Controls carry `data-xr-control`, and `beforexrselect` is cancelled on them so a button tap is never also a "place" tap.
- **Before placing:** an outline of the item's true outer footprint (W x D, from the precise bounding box) is drawn where it will stand, facing the viewer.
- **On Place:** the model drops about 12 cm onto its shadow over 250 ms (`settleOffset`; no motion under reduced-motion settings). This is cosmetic, with no physics engine and no collision or fit claims.
- **Anchors:** created inside the next animation frame (the spec requires an active frame).
- **Setup failures:** any failure after `requestSession` ends the session, so no camera feed is left without controls. The overlay is shown only once the session controller exists.
- If `requestSession` fails (camera denied, no DOM overlay) or the GLB fails to load in-session, the page shows "AR could not start…" and switches to the native viewer ("Open in phone AR viewer") when available, otherwise the hand-off panel.
- Real-device debug: append `?ardebug` to log the placement metrics (time to first placement, failed placements, moves, rotations) at session end.

## "View in my home" (as built)
- The built-in `ar-button` slot is hidden. Our own prominent button sits in the product info column (`ArSection`).
- The button appears only for the `webxr` or `native` mode above. `webxr` starts our session directly (no tips dialog: the session teaches in place); `native` calls `viewer.activateAR()`.
- The viewer stays mounted (hidden) while the Photos tab is shown, so AR can still launch from it.
- On devices without AR, show: "AR is available on compatible phones and tablets." Offer Copy link and an optional small QR code of **this page** for handing off to a phone.
- On click:
  1. `recordEvent({type:'ar_activation'})`, **once per page view** (an attempt, not a confirmed placement).
  2. Native mode only: show the AR tips first if the user hasn't dismissed them.
- On `ar-status: failed`, show the toast "AR couldn't start on this device. You can still explore the 3D model."

## Accurate scale
- Always display dimensions as `W × H × D unit`. A cm/in toggle changes the display only; the stored unit stays the source of truth.
- `ar-scale="fixed"` stops users from resizing the model in AR.
- **Scale check:** after `load`, compare `viewer.getDimensions()` (meters) with the entered dimensions, mapping x→W, y→H, z→D, with ±5 % tolerance.
  - All three within tolerance: badge "True-to-size model ✓".
  - Otherwise: badge "AR scale unverified", with a tooltip showing measured vs entered values.
- **Never** change `scale` to force a match. The admin ModelPreview shows the same check.

## AR tips (ArTips, native viewers only)
A dismissible bottom sheet on mobile, a popover on desktop. Steps:
1. Point the camera at the floor.
2. Move slowly to scan.
3. Tap to place.
4. Drag to move, two fingers to rotate.

"Don't show again" sets `arfurn:arTipsDismissed`. An "AR tips" link reopens the panel. All text is translated.

## In-app browser notice
- `detectInAppBrowser(ua)` returns `'instagram' | 'facebook' | 'whatsapp' | null`, matching `/Instagram/i`, `/FBAN|FBAV|FB_IAB/i`, and `/WhatsApp/i`.
- When it matches, show a dismissible banner: "For the best AR experience, open this page in Safari or Chrome", plus Copy link. Never promise that AR is blocked.

## Sample models (see [ADR-0013](../decisions/ADR-0013-sample-assets-measured.md) for what shipped)
- Use Khronos glTF-Sample-Assets GLBs (e.g. SheenChair, GlamVelvetSofa, ChairDamaskPurplegold). **Verify that each URL loads and that CORS allows it.** Fall back to copies in `public/models/`.
- Add USDZ only when a properly licensed file exists.
- The seed must also include products with **no model** and one with a **broken model URL**, so the fallback states can be tested.
- When `ios-src` is missing, model-viewer may generate a USDZ for Quick Look on its own. That is library behaviour; never present it as our feature. The editor's **AR readiness** panel (`features/ar/readiness.ts`) lists: 3D viewer, Android AR, iPhone AR (warning without USDZ), true size (scale check), and a warning above 15 MB.
