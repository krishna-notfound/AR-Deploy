# 10 · Internationalisation (public pages only)
Read when: adding public-page text, the language switcher, or localized product fields.
Decision: [ADR-0004](../decisions/ADR-0004-localized-content.md)

- `LanguageProvider` wraps the **whole app** (`RootLayout`, ADR-0044, 2026-10-29): public pages, dashboards, settings and sign-in pages. Admin and dashboard text goes through `t()` like the public pages (it was plain English before).
- `i18n/dictionaries/en.ts` is the master dictionary (`as const`). `TranslationKey` is derived from it.
- `pt.ts` is typed `Partial<Record<TranslationKey, string>>`, so missing PT keys are allowed.
- `t(key, vars?)` looks up the key in the current language, then English, then returns the key itself. In dev it calls `console.warn` for missing keys. Supports `{name}` interpolation.
- `localized(text)` returns `text[lang] ?? text.en`. When it falls back to English, wrap that element in `lang="en"`.
- Language order: `?lang=` for that visit only, then `localStorage` `arfurn:lang` (written when a switch is used; an old `sessionStorage` value is copied over once), then `navigator.language` starting with `pt`, then `en`. Keep `<html lang>` in sync (`pt-PT` / `en`).
- `LanguageSwitcher` (`src/components/ui/LanguageSwitcher.tsx`): the same "EN / PT" switch on every screen: public header, dashboard top bar (in the navigation drawer on phones), settings header, sign-in pages. Only the colour changes.
- Dashboard strings live in per-area files spread into `en.ts` and `pt.ts` (`en.admin.ts`, `en.business.ts`, `en.settings.ts`, `en.team.ts`, `en.products.ts`, `en.applications.ts`, `en.editor.ts`, `en.common.ts`, `en.ui.ts`, `en.auth.ts`, `en.site.ts`). Language is Portuguese of Portugal (pt-PT). Business and product data is not translated.
- Helpers: `tn(key, n, vars)` for `key.one` / `key.other`; `useFormat()` for dates, numbers and money in the current language; `errorText(error)` maps a service error to a translated sentence (the English `ServiceError.message` is for logs only). `i18n.test.ts` checks that every English key has a Portuguese entry with the same `{tokens}` and no empty value, and that `nav.ts` has no literal label.
- Application form texts (`apply.*`) can be overridden per language by the client in the Editor (design/12, `applyText(key, vars)`); the dictionary text stays the fallback.
- Prices: `Intl.NumberFormat(lang==='pt' ? 'pt-PT' : 'en-US', { style:'currency', currency })`. pt-PT vs pt-BR is still undecided; see [open-questions.md](open-questions.md) Q3.
- Key namespaces: `nav.*`, `catalog.*`, `product.*`, `ar.*` (button, tips, errors, scale), `share.*`, `inApp.*`, `common.*`.
