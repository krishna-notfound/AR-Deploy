## DT-1 audit: where dates and times are formatted

All dashboard code formats through `useFormat()` (`src/lib/useFormat.ts`) into `src/lib/format.ts`. Nothing shows a time-zone label anywhere.

- With the person's preferences (`usePreferences()`, loaded from the profile): `formatDate`, `formatDateTime`, `formatTime`, `formatRelative` use the profile time zone (database default and demo default `Europe/Lisbon`; an unknown zone falls back to Lisbon). Not UTC.
- Without preferences (public pages, signed out, while the profile loads, or if it fails): `formatDate` and `formatDateTime` use the browser's own zone (`Intl.DateTimeFormat` default). Not UTC either, so UTC appears only when the browser or the profile is set to UTC (the PreferencesSection sample uses UTC for its preview).
- Date-only series labels in charts (`src/components/charts/Charts.tsx:32`) are formatted in UTC on purpose (the day key is already a calendar date).
- `src/lib/format.ts:68` `shortMonth` uses UTC only to get a month name.
- Analytics days: `localDay()` in `src/services/analytics.ts` uses the passed zone; an unknown zone counts as UTC; the series keys use `toISOString().slice(0, 10)` on dates built in UTC (calendar arithmetic only).
- Date filters (`localDayBounds`, used by the Applications list in `supabaseCatalogService.ts:1365` and the mock): the browser zone, not the profile zone. This is the mismatch with times shown in the profile zone (default Lisbon).
- Real UTC output: `src/features/settings/RecoveryCodes.tsx:20` (file date, `toISOString().slice(0, 10)`); edge functions format emails in UTC (`_shared/email-templates.ts:75`, `account-security/handler.ts:601`).

After the decision, the quick fix is in two places: label in `useFormat` outputs where times are shown, and make `localDayBounds` take the same zone.
