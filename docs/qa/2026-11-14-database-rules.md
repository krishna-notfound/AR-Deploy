## Things to know before applying
- The new CHECK constraints are NOT VALID: existing rows are not scanned, but any later update of a row that breaks one fails. Run the two queries in the migration header on the testing project first (for example a business e-mail such as `shop@test` has no dot in its domain and now fails).
- Existing DB tests changed because they relied on the old gap: `migrations.test.ts` (re-saves of a published product now pass `keepModels: true`; the "published before the 3D rule" fixture is built with triggers off; one e-mail fixture `shop@test` became `shop@test.pt`) and `productCtaHidden.test.ts` (`keep_models: true`).
- Same P0002 "not found" pattern exists in other RPCs (`business_not_found`, `application_not_found`, `claim_invalid`, staff `model_request_*`). Not changed: the report names only `cancel_model_request`, and the staff ones go through Edge Functions that map the key to 404. Worth a follow-up if the owner wants every RPC 4xx.
- Verified here: vitest on all of `supabase/tests` (24 files plus the new one) and the touched client tests; `npm run typecheck` and `npm run lint` (0 errors).
