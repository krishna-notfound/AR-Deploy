# QA fixes, group auth-account (2026-11-14)

Verdicts follow the QA report of 2026-11-14, each checked against the code first. "NEEDS DEPLOY" means the fix is in the code but only works once the owner redeploys the edge function (and, for AUTH6, applies the migration).

| ID | Verdict | What I found | Fix and test |
|---|---|---|---|
| ACT-F1 | REAL | `AcceptInvitePage` called `auth.updateDisplayName`, which wrote only the auth `user_metadata`; `profiles.display_name` (read by the required "name" setup step) stayed empty. | The page now calls `account.updateProfile({ displayName })` (writes the profile and the metadata). `auth.updateDisplayName` was unused and is removed. Test: `src/test/auth.test.tsx` "saves the name to the profile". |
| EF-15 | REAL | The result of the name save was ignored. | A failed save shows `invite.nameFailed` (EN/PT), stops before `completeOwnerOnboarding`; Continue retries without asking for the password. Test: "a failed name save is shown". |
| AUTH1 | REAL, NEEDS DEPLOY | `applyPassword` swallowed an `endSessions` failure and the function still answered `signedOut: true`; the toast said every device was signed out. | Function answers `signedOut: false` (and audits `sessions_end_failed`); the browser retries a global sign-out once, then `changePassword`/`resetPassword` return `{ sessionsEnded: false }` and the toast says other devices may still be signed in (EN/PT). Tests: `handler.test.ts` (change and reset), `supabaseAccount.test.ts`. |
| AUTH2 | REAL | A signed-in account with no role (`user` null, `signedInEmail` set) kept the code form with a spinner for ever. | The page shows "You're signed in as X, but this account has no invitation waiting" with a sign-out (EN/PT). Test: "a signed-in account with no invitation waiting". |
| AUTH3 | REAL (ADR-0069) | Max 128 characters in the app and the function, none on the owner invitation; bcrypt uses 72 bytes. | One rule: 12 characters minimum, 72 bytes maximum (`PASSWORD_MAX`, `passwordTooLong`) in Settings, reset page, owner invite, staff join, mock/Supabase account service and the function. Docs line in CLIENT_HANDOVER updated. Tests: handler (73 ASCII, 37 two-byte, 72 ok), supabaseAccount, ResetPasswordPage, auth.test (owner invite). Does not touch the `accept-member-invite` function (staff join), which still counts characters. |
| AUTH4 | NEEDS OWNER DECISION | `logout` calls `auth.signOut()` with the default global scope. No ADR or DECISIONS row covers it; the code even words a "this device only" fallback, so global looks intended, while the S1 spec lists a separate "Sign out other devices" button. | Not changed. Options: (a) keep global (Sign out and Switch account end every device); (b) plain Sign out and Switch account use `scope: 'local'`, "Sign out other devices" stays the way to end the rest. |
| AUTH5 | REAL, NEEDS DEPLOY | After the password was set, a failed `service_log_account_event` threw and the caller got an error for a change that had happened. | The audit write after the change is best effort (`logEventQuietly`, logged to the function log). Tests: change and reset with a failing audit rpc. |
| AUTH6 | REAL, NEEDS DEPLOY + MIGRATION | `service_use_recovery_code` consumed the code before the factor was removed; a failed removal burned the code. | On a failed `wipeSecondFactor` the function calls the new `service_restore_recovery_code` (only a code spent in the last 5 minutes, service role only) and rethrows. Without the migration the call fails quietly and behaviour is as before. Test: "when removing the authenticator fails, the spent code is given back". |
| AUTH7 | REAL, NEEDS DEPLOY | New recovery codes were saved, then a failing audit write threw before the codes were returned; Retry then needed an emailed code. | The audit write is best effort, so the codes are always returned once saved. Test: "a failed audit write still returns the saved codes". |
| AUTH8 | REAL | `refreshAccess` returned at once for anyone without platform access, so a removed business owner's tab never reloaded the account. | On the focus/visibility/aal1 cadence a business owner's membership is read again (`auth.getCurrentUser`); a changed or missing business reloads the account (the tab leaves the dashboard). Test: "a business owner who was removed while a tab is open". |
| AUTH9 | REAL | `setPending(false)` right after a successful sign-in left the button clickable until the account loaded. | Busy until the account loaded, failed, a role-less account is shown, or 15 s pass. Tests: LoginPage (fails without the fix; refused sign-in re-enables). |
| AUTH10 | PARTLY REAL | Starting a setup in a second tab unenrols the first tab's unverified factor (needed: Supabase refuses a second factor with the same name, and the existing test pins it). The first tab then showed "That code didn't match". | The first tab now gets `totp_setup_replaced` ("replaced by one started in another tab", EN/PT) and a Try again that starts afresh. The two tabs can still replace each other; only the message is fixed. Tests: supabaseAccount, TotpSetup. |
| EF-14 | REAL | After `acceptInviteCreate` succeeded, any sign-in failure showed one generic line and the form stayed as it was; pressing Create again hit a used invitation. | Once the account exists the form is locked and only retries the sign-in (button "Sign in", link to /login); the message adds the real reason (network, rate limit...). New test file `src/features/join/JoinPageSignIn.test.tsx`. |
| BL-1 | REAL, NEEDS DEPLOY | `SWEEP_BUCKETS` had no `ar-models`, and `request_closure` removed nothing. `sync-ar-models` writes `ar-models/{business}/{product}/{variant\|base}/{format}-{id}.{ext}` (two folder levels). | `ar-models` added to `SWEEP_BUCKETS`; `removeBusinessFolder` walks as many folder levels as the bucket has (`SWEEP_DEPTH`). New dep `removeArCopies` runs at `request_closure` (folder removed, `public_url` cleared on `product_models` and `product_variant_models`), failure noted in the event (`ar_copies_removal_incomplete`) and the closure goes on; completion reports `storage_sweep_incomplete` as before. After "Cancel request" the browser asks `sync-ar-models` to copy the published products again. Tests: handler (sweep depth 2, failure, request, staff). |
